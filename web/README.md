# CPU Physics Olympiad classroom

The homepage and /classroom/ open the official course. Students sign in to see the problem sets their teacher has released. The Cloudflare Worker stores users, hashed passwords, expiring sessions, invitations, private packages and publication settings in a SQLite-backed Durable Object.

From web/, run npm run check, npm test and npm run build. Run npm run dev:classroom for the full local site on port 8787. The Astro development server on port 4321 proxies its classroom API to the local Worker on 8787. Local Wrangler storage is independent of production. On a fresh instance, configure a random OWNER_SETUP_TOKEN of at least 32 characters in an ignored .dev.vars (local) or a Wrangler secret (production), then use that code to register the primary administrator. The setup code stops working once that account exists.

The first account is the sole primary administrator. Only this account can create or invite other administrators, promote students, or change or delete an existing administrator. Its primary status cannot be assigned, transferred or removed in the classroom. Ordinary administrators can manage students, issue student invitations, upload problem sets and control lesson releases. Both levels can view the account directory. Under Manage accounts, the primary administrator can reset passwords for other administrators and students. Ordinary administrators can reset only student passwords. A reset signs the target user out of all sessions. During migration the configured original username and first database row identify the existing owner. Unused administrator invitations issued before this distinction must be reissued by the primary administrator. Access changes revoke that account’s sessions.

Under **Manage classroom → Quick student registration**, enter the seven-digit CPU account number, choose **Valid for**, then select **Allow registration**. The default is 14 days. Either administrator role can choose a preset, enter a whole number from 1 to 3,650 days, or select **Until used or cancelled**. The same choices are available when creating a student invitation with a custom code or link. Administrator invitations expire after 24 hours.

When a student enters a CPU account number without a current authorization, the registration screen opens **Request access**. The student enters their name, school year (S1–S6), and Physics Team membership, then verifies the matching school Google account. Non-members must also explain why they need access. Both administrator roles can review submissions under **Manage classroom → Student access requests**. Approving authorizes registration for the selected period. The student can then register using the same number. Declining closes the pending request.

Use **Pending student registrations** to cancel a student's unused authorizations, including custom invitation links for that school account. If an older email-as-code invitation is missing from the list, choose **Find registration** with the seven-digit account number. To change a pending authorization’s validity, cancel it and create a new one. Repeating quick registration for an already authorized number keeps its existing validity. After signup, manage the student's access under **Manage accounts**.

To create a custom student invitation, enter the school Google email (s followed by seven digits at cpu.edu.hk). Use that address as the code, choose a different code, or generate a random code. Students can register with just the seven digits of their CPU account (for example, 2020123 for s2020123@cpu.edu.hk), or open the invitation link. The number looks up the active student invitation. Creating the account requires a signed Google Workspace identity for the exact invited email. Existing students continue to sign in with their classroom credentials. An older student invitation whose code is the school email can be verified. Reissue older student invitations that have no school email binding. Administrators can also upload compiled .cpu.json packages and preview the private drafts. Open a set, select the student visibility for questions and solutions, then save. Replacing an existing set creates a new private revision. Students sign in to see released content. Releasing solutions alone shares the worked explanations, which may reference the questions. Hiding a set prevents future requests; students can keep material they already viewed.

The authoring contract and a complete TSX example are in public/course-package-guide.md. Run npm run pack:lesson -- ENTRY.ts OUTPUT.cpu.json with trusted local source. Deploy the reviewed build to the configured Worker with npm run deploy. Keep private packages and admin credentials out of static assets and out of source control.

## Configure school Google signup

In Google Cloud Console, create or select a project and open Google Auth Platform. Complete Branding with the classroom name, a support email and developer contact. Use Internal audience when the project belongs to the school Workspace organization. For an external project, allow the intended school users through the Audience settings and the school’s Google Workspace app-access policy.

In Clients, create an OAuth client of type Web application. Add the exact site origin printed in the classroom’s Google signup settings under Authorized JavaScript origins (for production, https://cpu-physics-olympiad.ngantszhang1008-mc.workers.dev). The popup returns the credential via JavaScript; leave redirect URIs empty. Local testing requires an authorized localhost origin. Sign in as the primary administrator, open Manage classroom → Google signup settings, paste the public Client ID, and save. Only the public client ID is needed. Google verifies the account at signup. The Worker checks the signature, audience, issuer, nonce, Workspace domain, verified email and exact invitation before creating the classroom account.

## Password recovery

**Forgot password?** accepts a classroom username. New student registrations completed with a seven-digit CPU number save the exact Google-verified school address for recovery. The app never infers a recovery address from a username. Older accounts and accounts created another way use **Manage accounts → Reset password**. An administrator should confirm the requester's identity separately before assigning a password. Primary administrator protection and the administrator role hierarchy also apply during recovery.

For delivery from a Gmail account you control, create a standalone project at [Google Apps Script](https://script.google.com/home), paste the contents of `tools/classroom-mail.gs` into `Code.gs`, and save. Generate a random secret (for example, run `openssl rand -hex 32` locally). In **Project Settings → Script properties**, add `GOOGLE_MAIL_SECRET` with that value. Choose **Deploy → New deployment → Web app**, execute as **Me**, and grant access to **Anyone** so the classroom Worker can reach it. Authorize the mail permission as the sender. Copy the deployment URL ending in `/exec`.

In Cloudflare, open **Workers & Pages → cpu-physics-olympiad → Settings → Variables and Secrets**. Add `GOOGLE_MAIL_SCRIPT_URL` with the deployment URL and `GOOGLE_MAIL_SECRET` with the matching secret. Use type **Secret** and deploy. Test with an eligible classroom account whose school inbox you can check. Gmail delivery uses the script owner's quota. [Google Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas)

Alternatively, to use Resend, verify a sending domain with Resend and create a sending-only API key. In the Worker’s **Settings → Variables and Secrets**, set secret `RESEND_API_KEY` to that key and `RESET_EMAIL_FROM` to a sender address on the verified domain, then deploy the settings. Alternatively, from `web/` run `npx wrangler secret put RESEND_API_KEY` and `npx wrangler secret put RESET_EMAIL_FROM`. The checked-in `CLASSROOM_ORIGIN` sets the trusted reset-link destination. Disable click tracking for these links. [Cloudflare’s Resend setup guide](https://developers.cloudflare.com/workers/tutorials/send-emails-with-resend/)

Links expire after 30 minutes and are single-use. A completed reset invalidates outstanding links and signs the user out of existing sessions. If email is unconfigured or the provider rejects delivery, a manual request appears in **Manage accounts**.
